# SOP Runner

SOP Runner は、Word の手順書（SOP）を 1 ステップずつ実行し、実施記録を残すためのオフラインな単一 HTML ファイルです。ブラウザで `sop-runner.html` を開き、`.docx` をドラッグします。ページは文書をステップに分け、一度に 1 ステップだけを表示し、コマンドはコピーでき、記入が必要な箇所には入力欄を作ります。各ステップは確認するまで次へ進めません。最後に、証拠として残せる Word の実施記録をダウンロードします。このファイルはネットワーク要求を出しません。Content-Security-Policy が外部接続をすべて禁止し、使用するライブラリ（JSZip 3.10.1）は HTML に埋め込まれています。

画面上のラベルは中国語です。サンプル手順書は日本語です。Word への出力は初期状態で日本語の見出しになり、中国語にも切り替えられます。

## 機能

- `.docx` をページへドラッグするか、**选择 .docx 文件** から選びます。古い `.doc` は拒否されます。Word で「名前を付けて保存」し、`.docx` にしてください。
- 手順を自動で分割します。
  - 見出し（Heading / 見出し / 标题 などのスタイル、アウトライン レベル、または `第1章` や `1. 事前準備` のような短い太字行）は節の名前になります。
  - 最上位の番号付き項目が、それぞれ 1 ステップになります。最上位の箇条書きも同様ですが、番号付きステップの下にある箇条書きはそのステップに残ります。
  - 空のセル、空欄マーカー、または結果列（例: `確認結果`）を含む表は、先頭行が列見出しに見えるとき、データ行ごとに 1 ステップになります。そうでないときは表全体で 1 ステップになります。
  - 期待結果、確認内容、判定基準、expected result などのラベルが付いた行は、期待結果として別に表示します。
- 一度に 1 ステップだけを表示します。まだ到達していないステップはロックされ、現在のステップを確認するまで開けません。
- 等幅フォントの行や、`$`、`#`、`PS>` などのプロンプトで始まる行はコマンドとして表示します。**复制** はプロンプトを除いてコピーします。行内のコードには別のコピーボタンがあります。
- 記入が必要な箇所に入力欄を作ります。対象は `＿＿＿` と `___`、`（　）`、`【　】`、`［　］`、`[ ]`、`「　」` のような空の括弧、`（記入）`、`□` / `☐`、`確認結果：` や `記入：` のようにコロンの後が空のラベル、記録表の空セルです。より明確な空欄がステップ内にないときは、`記入`、`填写`、`填入` と書かれた文からも入力欄を作ります。
- 種類は文面から推定します。時刻（`作業日` や `時刻` など。**现在** ボタン付き）、結果（`結果` / `判定`。**OK** / **NG** ボタン付き）、チェック、またはテキストです。空欄の直後に書かれた単位（`件` など）は残します。
- 任意でない項目が埋まるまで **确认** は押せません。各ステップには任意の備考と、**标记为异常** のチェックがあります。
- 開始前に構成を直せます。実行中に **重置进度** を押すと編集に戻ります（入力済みの値は消え、編集したステップは残ります）。
  - 節、タイトル、操作内容、期待結果を書き換えられます。
  - 上へ、下へ、次のステップと結合、または **操作内容** のカーソル位置で 2 つに分割できます。
  - ステップの挿入と削除ができます。
  - 入力欄の追加、削除、再検出ができます。ラベル、種類（文本 / 时间 / 结果(OK/NG) / 勾选）、単位、任意かどうかを設定できます。
  - 操作内容では、行全体をバッククォートで囲むとその行がコマンドになり、行の途中のバッククォートは行内コードになります。文面を直したあとは **重新检测输入** で検出し直します。
- ホームから保存済みの進捗を再開できます。同じ未変更のファイルを再度ドロップしたときも、続きから実行できます。
- 横向き A4 の Word 記録（`simple-table`）と JSON バックアップを出力します。実行の開始と Word の出力には、実施者名が必要です。

## 入手方法

インストールは不要です。このリポジトリの [`sop-runner.html`](sop-runner.html) をダウンロードしてください（リポジトリ直下のこのファイルがプログラムそのものです）。ダブルクリックで開きます。ファイルが手元にあれば、実行にネットワークは不要です。このリポジトリに GitHub Release はありません。ツリー内の HTML ファイルを使います。

会社の PC では、先にブラウザを確認してください。

1. 同じリポジトリの [`js-test.html`](js-test.html) をダウンロードします。
2. ダブルクリックして開き、**点我测试** をクリックします。
3. 緑の表示が出れば、その PC はローカル HTML と JavaScript を許可しています。`sop-runner.html` を使えます。同じページは `localStorage` が使えるかも示します（進捗の自動保存に使います）。
4. クリックしても何も起きない場合、ローカルファイルの JavaScript が無効です。Microsoft Edge または Google Chrome を試すか、IT に相談してください。このテストページはネットワークに接続せず、ファイルも読みません。

架空のサンプル [`sample/Webサーバ定期パッチ適用手順書.docx`](sample/Webサーバ定期パッチ適用手順書.docx) でも試せます。

## 使い方

1. `sop-runner.html` を開きます。
2. `.docx` を破線の領域へドロップするか、**选择 .docx 文件** をクリックします。ホームには、ファイルはこのブラウザの中だけで解析されると書かれています。
3. 同じファイル名かつ同じ内容の進捗がこのブラウザにある場合、**确定** で続きから、**取消** で解析し直して上書きします。
4. 取り込み後は編集モードです。分割がおかしいステップを直し、**执行者**（必須）を入力して **开始执行** をクリックします。
5. 強調されているステップを実施します。コマンドをコピーし、記録欄を埋め、必要なら備考や異常の印を付けます。必須項目が空のうちは **确认** を押せません。最後のステップを確認すると完了ページが開きます。
6. 左の一覧から、確認済みのステップを見返せます。現在のステップの直前だけ、確認を取り消せます。未到達のステップは開けません。
7. 完了ページで要約を確認し、**导出语言**（初期値は **日本語**、**中文** も選べます）を選んで **导出 Word 执行记录** をクリックします。どちらの言語でも、ダウンロード名は `{手順書名}_実施記録_{YYYYMMDD-HHmm}.docx` です。**导出 JSON 备份** は手元に `{手順書名}_run_{YYYYMMDD-HHmm}.json` を書き出します。
8. **返回首页** のあと、その進捗は「保存済みの進捗」の表に残ります。**继续** で開き直し、**删除** でこのブラウザから削除します。**导入 JSON 备份** は、以前に書き出したバックアップを戻します。進捗を開いているときに **重置进度** を押すと、記録値・備考・確認時刻が消え、編集モードに戻ります。編集したステップは残ります。

## 進捗の保存とプライバシー

進捗はこのブラウザの `localStorage` に保存されます。キーは `sopRunner:v1:` で始まり、その後にファイル名とファイル内容のハッシュが続きます。Word ファイルを変更するとハッシュが変わるため、別の進捗として残ります。実施者名はこのブラウザの `sopRunner:executor` にも記憶され、次回は初めから入ります。編集のたびにすぐ保存します。ブラウザが書き込みを拒んだときは、保存失敗のメッセージが出ます。

ページの Content-Security-Policy は `default-src 'none'` で、`connect-src 'none'` です。解析、保存された進捗、出力はすべてこのマシン上に残ります。Word と JSON は、自分でディスクに保存するファイルです。そのページのオリジンのサイトデータを消すと、保存済みの進捗も消えます。

## 必要な環境

ローカル HTML の JavaScript を実行できる最近のブラウザを使います。`js-test.html` は、クリックしても反応がない場合に Microsoft Edge または Google Chrome を案内します。進捗を自動で残すには `localStorage` が必要です。手順書は `.docx`（Office Open XML）である必要があります。

## 実在の手順書はコミットしない

実在の SOP、実施記録、その他の会社データをこのリポジトリにコミットしないでください。[`sample/`](sample/) のファイルは架空です。[`sample/make_sample.py`](sample/make_sample.py) が生成し、文書本体にもサンプルであると書かれています。登場するホスト名は文書用の例です（`example.local`、`192.0.2.0/24`）。

## リポジトリの内容

| パス | 内容 |
| --- | --- |
| [`sop-runner.html`](sop-runner.html) | 開く単一ファイル |
| [`js-test.html`](js-test.html) | ローカル HTML + JavaScript の確認 |
| [`sample/`](sample/) | 架空の手順書と、それを作るスクリプト |
| [`src/`](src/) | `parser.js`（分割と入力検出）、`export.js`（Word 出力）、`app.js`（画面）、`app.css`、`template.html` |
| [`build/build.js`](build/build.js) | `src/` と JSZip から `sop-runner.html` を組み立てる。再ビルド時の JSZip は `build/node_modules` から読む（[`build/package.json`](build/package.json) の `jszip`）。配布用の HTML には、すでに入っている |
| [`tests/`](tests/)、[`run_tests.sh`](run_tests.sh) | Playwright のエンドツーエンド、出力の検証、オフライン検査。`./run_tests.sh` は HTML を作り直してこれらを再実行する |
| [`screenshots/`](screenshots/) | 上の画面写真 |

Word 出力は `src/export.js` の 3 層です。`RecordModel.build()`（データ）、`ExportTemplates[name].render()`（体裁）、`DocxWriter.pack()`（`.docx` への梱包）。ページは `simple-table` テンプレートで出力します。会社の証跡様式に替えるには、`ExportTemplates` にエントリを追加します。たとえばその様式の `word/document.xml` を文字列として埋め、`{{executor}}` などのプレースホルダを置き換え、表の行を繰り返します。
